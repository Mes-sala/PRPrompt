# R3：保留计算配方，修复精确并列的诊断断言

R2 在 Chameleon、1-shot、支持 seed 30093009、训练 seed 0 的 F100OneShotAdapt 单元开始训练前退出。该分片已封存 249 个单元；控制器停止派发并等待其余已启动任务收尾，原源码、日志和结果保留。

原断言比较两个 float32 概率矩阵的首个 argmax 索引。两张 GPU 各五次诊断均显示：两次教师分数完全相同，但温度变换前出现精确并列，变换后区分了这些数值，导致首个最大索引不同。精确最大值集合仍有交集。原 CPU 前缀诊断在未修改的滤波器断言处退出，不宣称 CPU 完整前缀通过。

R3 保留历史源文件字节，仅在加载 optimizer_prompt 时将这一条诊断检查改为：每行两个概率矩阵的精确最大值集合必须有交集。没有 epsilon，没有概率重算或替换；非并列的顺序反转与 NaN 仍立即拒绝。原 argmax 断言是否成立及并列行数继续记录，不写成原断言全部通过。

每个 F100 单元另保存 `prefit_order.npz`，记录温度变换前教师概率和原门控概率。文件在 query 评分前写入，SHA 进入单元审计；状态内的同一数组由服务器 Torch 核对，独立 NumPy 重算精确并列判据及哈希。复制的父参考携带相同诊断文件，参考不计作新拟合。

CPU 与两张 GPU 的真实 1/3/5-shot、100 步旧配方对照通过；CPU 分数、表示、tokens 完全一致，GPU 按原有数值界限记录差异，不声称逐位一致。故障注入验证精确并列可识别、非并列反转及 NaN 拒绝、RNG 不变、保存数组可独立重放、篡改数组即使更新文件 SHA 仍被拒绝。原失败支持单元也在两张 GPU 完成 100 步验证，全程没有 query 评分，不计正式结果。

R3 使用独立源码快照与计划，保持七数据集、原 Edgepred_Gprompt、1/3/5-shot、20 支持抽样、3 训练种子、100 步、支持内选参和配对统计。数据与 checkpoint 逐字节相同，正式单元从零开始，R2 结果不混入 R3。主实验仍需 31,500 单元与 15,120 固定表示探针，随后执行 3,780 个 F100 路由对照及 2,520 个父参考。只有在实际旧进程退出、失败证据和清单保留后，才能启动 R3。

工程证据见 [精确并列工程复核](边界实验_R3_精确并列工程复核.json)。R3 随后通过服务器与独立本地 smoke 复核，记录见 [独立 smoke 验收](边界实验_R3_独立smoke复核.json)。正式覆盖、完整数值验收、回传和论文方案判断仍待完成；smoke 不提供正式收益结论。
