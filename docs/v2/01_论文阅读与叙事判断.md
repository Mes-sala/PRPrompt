# 从本地原文到 PRPrompt 的叙事选择

日期：2026-09-30。阅读对象为本地英文 PDF，清单和 SHA256 见 [paper_sources.json](paper_sources.json)。页码均为 PDF 页码。没有把译文、论文文件名或旧汇报结论当作原文证据；完整论文不上传到本仓库。

## 1. 这些论文究竟围绕什么展开

| 论文 | 问题与核心对象 | 设计为何属于同一条论证 | 实验如何回答问题 | 对本项目的启发 |
|---|---|---|---|---|
| GPPT，KDD 2022，pp.1–2、4–7 | 分类任务与边预测预训练不一致；将节点与类别表示配成待判别的 token pair | 结构与任务 token 服务于同一个任务改写，而非互不相干的性能补丁 | 同监督、联合训练、预训练迁移比较，再检查少样本与适配效率 | 先说明提示如何进入预训练模型的使用方式，再解释参数化 |
| GraphPrompt，WWW 2023，pp.1–2、4–6 | 用子图相似度统一预训练和下游任务，再用任务提示调整读出 | 统一模板定义任务，提示区分任务需求，两者有明确依赖 | 节点/图任务、少样本、提示作用；不是只展示模块相加 | 不能把“使用类别原型分类”当作我们的独有贡献 |
| GPF/GPF-plus，NeurIPS 2023，pp.1–3、5–8 | 不为每种预训练任务手工设计模板；在特征空间实施提示 | 共享向量和注意力提示基是同一个特征变换的两种参数化 | 固定预训练模型比较完整微调与提示；跨预训练策略 | 节点相关提示、提示基加权组合已有直接先例；我们的区别必须落在路由依据及位置 |
| All in One，KDD 2023，pp.1–2、4–8 | 不同粒度图任务难以共享提示形式 | token、token 结构、插入方式、任务改写和元初始化围绕多任务适配服务 | 完整方法对比与机制实验并存 | 不是“模块越少越好”，而是每个设计都必须回答同一个任务问题；不可挪用其额外元训练监督设定 |
| MultiGPrompt，WWW 2024，pp.1–2、4–7 | 单一预训练任务知识不足，多任务又存在干扰 | 预训练 token 与组合/开放提示分别对应知识学习和提取 | 多任务预训练、下游适配和完整基线比较 | 不能仅加载一个普通 checkpoint 就把移植分支叫作完整 MultiGPrompt |
| UniPrompt，NeurIPS 2025，pp.1–6、8 | 许多表示层提示和分类器作用重合；不同预训练模型下适配不稳定 | 从提示/分类器职责出发，设计输入拓扑提示 | 线性探针是重要对手；同域与跨域分别验证 | 必须正面比较 FrozenLinear。其线性假设下的函数表达讨论不等于所有提示都无效，也不应据此声称任意优化轨迹等价 |
| GraphTOP，NeurIPS 2025，pp.1–2、4–8 | 把图拓扑作为提示的作用对象 | 重连、连续化、局部约束和正则都使同一个拓扑提示可学习、可计算 | 多数据集、多预训练策略、完整方法和局部设计分析 | 我们没有改拓扑，不能沿用“修复图结构”的问题与贡献 |
| DAPrompt，AAAI 2026，pp.1–2、4–7 | 异配图的结构可靠性与语义混杂 | 预训练结构学习和两种提示围绕双重对齐展开 | 监督模型、预训练微调、Prompt 三类主对比 | 不能把普通预训练模型上的简化移植列为原版 DAPrompt；其异配叙事不能直接移植给两跳平滑的我们 |
| ProG，NeurIPS 2024 Datasets and Benchmarks，pp.1–5、18 | 各方法协议和实现不同，使比较失真 | 统一模型、预训练策略、数据与评测维度 | 监督、预训练微调、提示，并报告效率与预训练依赖 | 方法名不是可比性的证明。必须同时写清 backbone、预训练、读出、标签预算与选参方式 |

这些论文也做机制实验或消融。可借鉴的是“先有完整方案与外部对比，再用问题明确的分析解释方案”，而不是把顶会叙事理解成完全不需要机制证据。用户要求的新主线不采用模块开关网格；必要分析改为有语义名称的提示对照。

## 2. 对 PRPrompt 最有约束力的三个事实

**加权提示基不是新的抽象。** GPF-plus 已使用节点相关权重组合可学习提示基。PRPrompt 应解释：为什么用支持标签确定的类别原型关系组织路由，而不是从极少标签同时学路由和提示内容。这个问题可以被实验否定；不能凭设计直觉宣布固定路由一定更好。

**分类原型与路由原型的角色不同。** 本方案的原型先在属性空间中构造，决定每个节点接收什么提示；最终分类由所有线性读出方法共用的普通线性头完成。这样可以明确指向“任务条件如何进入冻结编码器”，而非把原型分类器包装成新提示。

**使用预训练模型不代表从中获益。** 如果属性原型或属性岭回归已经解释了结果，或者随机冻结编码器上的同一提示同样有效，就不能宣称提示有效提取了预训练知识。新计划把这些反例放进主对比或机制对照。

## 3. 选择一条可检验的叙事

本版本回答：**在每类只有少量标注时，能否用支持集原型关系固定节点的提示路由，只学习少量类别提示向量，使一个冻结的 GCN 获得任务相关的内部表示？**

这比“修复预训练与下游的一切差距”更窄，也比“几个组件各自提升性能”更容易验证。它承认两个限制：当前注入实现依赖两层 GCN；属性平滑和全图统计具有结构假设及传导式信息条件。没有证据时，不写通用骨干适配、未见类别泛化、跨图迁移或最优性能。
