# R137后备草案：在预条件特征基中运行Adam

来源：[SOAP原文第4节算法3/4](https://arxiv.org/html/2409.11321v2)、[官方preliminary仓库](https://github.com/nikhilvyas/SOAP)。固定commit `a1e553530fde97d0e6b307d7c82ac6d38b072340`；源码/许可证保存为 `soap_official_snapshot.py`/`soap_official_LICENSE`，完整克隆为 `references_SOAP`。这次核对了实际step/project/project_back/update_preconditioner/eigh/QR，而非只看摘要。

论文核心是把梯度转到预条件矩阵的特征基，再在该坐标系维护Adam二阶矩并转回；特征基更新采用幂迭代加QR。与累计Shampoo方向、Muon当前动量多项式均有实际算法区别。语言模型实验不证明图Prompt准确率，不能套用论文速度/收敛结论。

当前源码的实现边界（代码核对）：首次调用只从梯度初始化Q而不更新参数；后续更新后才用该次梯度刷新预条件统计；每10步QR，方差历史只按估计特征值排序重排，不能擅自换成“完整协方差旋转”还称官方实现；一阶矩在换基前转回、之后重新投影。eps在原始二阶矩平方根上相加、偏差修正在步长上，不能要求与本地torch Adam分母约定位精确一致。

`probe_soap137.py`用原样官方源码在CPU float32、7×128矩阵运行21次梯度调用（适配lr.01/betas .9,.999/无额外weight_decay），观察20次实际参数更新、首次no-op、Q正交与参数有限、原梯度未修改。`soap137_native_probe.json`仅是合成运行诊断；不是独立更新重构，也不是Cora训练或准确率结果。

拟迁移时保持Cora原late+scale2 CE+KD+正则、896token和k50。必须明确100梯度调用=99次SOAP更新，保留同调用数的恒等基SOAP/冻结初始特征基和原Adam100（必要时Adam99预算对照），不能漏掉warm-up后把预算当完全相同。原Adam强根不会因SOAP源码存在而替换；最终参照是否增加R136固定候选取决于其完整确认结论。

审计前置：真实图初始梯度常有退化子空间，不同eigh实现的特征向量在简并空间未必相同；需要封存实际Q、验证正交性/特征残差和QR更新关系，再对实际Q进行独立NumPy坐标变换/矩状态/参数回放，不能以简单逐元素比对两个合法特征基判错或静默修改训练基。必须同时保存排序索引和预条件状态，区分“验证实际合法基”与“独立重现相同基”。只用验证过的构造开始正式训练。
