# 多轮 Prompt 方案失败归因与研究反思

初稿日期：2026-09-10；更新日期：2026-09-15。范围：R³Prompt、RCCP、CNIP、STSP、CDP、RGP-MAE，以及 ASP 项目中的三轮输入方案 ASP、SIP、SCP。保留原文件名与历史决策，新增复盘见第 9—13 节。

> 后续研究决策更新（2026-09-10，依据用户反馈）：停止将现有自研方案，包括 RCCP 的局部正结果，作为后续研发优先项。保留其结果作为历史证据。研究重心转向 ProG 既有 Prompt 的忠实复现与统一比较、近两年 Prompt 的集成评测、近几年预训练方案的更新评估。输入位置与图结构是优先研究方向；完成证据积累后再设计新方法。本文第 8 节原有“继续窄诊断/独立复现”的建议由此更新覆盖。具体安排见《ProG统一评测与预训练更新研究路线》。

本次没有重新训练。R³、RCCP、CNIP、CDP 的数值主要引用已有复盘和诊断报告，未逐项重新审计全部原始运行；STSP 的补充统计直接读取本地 JSON 制品，以标准库重新汇总。以下把“观测事实”“机制解释”“尚未定位的问题”分开；不将未获支持等同于所有可能实现均已被否定。

2026-09-15 更新口径：阅读 ASP 三份设计、综合报告和实际实现，核对全部 4140 份实验 JSON 的 SHA256 与既有审计清单一致，并从原始记录重算本文新增的固定/随机对照差值和选择分布。本次未重新训练，也未重新执行既有逐概率审计；表中置信区间沿用已保存的配对汇总。SIP、SCP 是 ASP 项目的第二、第三轮方案，不是独立目录；本文 SCP 指输入幅度校准方案，不指文件传输命令。

**核心判断：这几轮反复缺少的，是从目标任务的实际瓶颈到有效适配动作的证据链。** 操作差异、数学性质、参数节省和非零梯度都已得到较多关注，但新增信息是否值得使用、动作是否能提高泛化、少样本能否选出动作，往往未分别成立便进入完整实验。

## 1. 先修正“这些方案都失败了”的分类

| 方案 | 原始主张 | 当前证据支持的判断 |
|---|---|---|
| R³Prompt | 冻结模型扰动响应指导消息角色与传播修正 | 响应内容的独立价值未建立，完整组合不值得继续作为优先主线 |
| RCCP | 少标签学会排除返回贡献，利用非线性重组改善表示 | 学习强度的主张未成立；固定校正在 GPPT 上有经过多轮诊断保留的正证据；精确非线性必要性未建立 |
| CNIP | 中心—邻域混合响应提供新增判别信息 | 默认配置总体负迁移；GraphCL 有窄正信号，尚不足以支撑通用主线 |
| STSP | 伪任务学习的低维提示空间及稳定性约束帮助真实任务 | 已有训练，旧 README 状态落后；有效先验、稳定性独立贡献和真实任务净收益均未充分验证 |
| CDP | 类差方向上的邻域收缩保护判别信息 | 两种 head 均无稳定增益；既有不动作情形，也有动作明显但负迁移情形 |
| ASP | 用输入平滑/锐化校正冻结编码器的任务频率偏好 | Cora 有有限增益，CiteSeer 未通过门槛；真实结构优于置换方向，但不足以证明整体方案值得推进 |
| SIP | 由支持集软语义重构输入，让冻结编码器利用任务信息 | 对弱 frozen 有大幅收益，语义/结构对应也有价值；再经编码器的完整流程未超过直接扩散属性分类 |
| SCP | 联合校准输入幅度与结构残差 | 对 frozen 和 scale-only 有增益；未超过强属性基线，且 Cora 未超过固定尺度，适合保留为输入校准诊断 |

早期 GCP 是材料记录的“查重后撤回首选”，不能列作实验失败。DHBP 等候选也不能因出现于方案排序便视为已被效果实验否定。本报告不重新核查这些方向的外部新颖性。

## 2. R³Prompt：信息价值没有成立，修复可训练性未能补足它

原方案链路是：成组结构扰动 → hidden response → 消息角色 → 跨层控制 → 分类收益。每个箭头都需要证据。

最新复盘中，Cora full 相对 frozen_base 仅 +0.028 个百分点，反而低于 random_response 0.100 个百分点、低于 endpoint_only 0.072 个百分点；Citeseer 对这两种输入对照也只有 +0.033、+0.061 个百分点。两数据集对应配对中位差均为 0。新增响应没有显示稳定的信息优势。

这不是简单的“控制器完全没学动”：最新 Cora 最终层平均节点干预比约 12.17%。旧 Bypass 修复后，Cora 从 31.13% 回到 34.96% 左右，说明工程修复有价值；但 full 对 no_bypass 仅 +0.011 个百分点，不能据此证明 Bypass 是有效模块。

**较有依据的归因：把模型对扰动的敏感性，当作可由极少标签解释的任务信号，学习链路过长。** 响应说明“会发生变化”，没有直接说明“变化对当前分类有利”。原稿中的 support loss-response 排序监督未进入已测实现，任务方向主要由少样本控制器自行估计。

另有三个风险，但不能冒充已隔离的根因：编码探针解码可能串扰；探测时边衰减并重新归一化，而执行时调整消息/旁路，测量与动作不完全相同；Correct、Bypass 的作用部分重叠，有限监督难以识别分工。

稳定化还收窄了动作空间：当前默认范围的 Correct 单独不能反转原消息符号。原始“signed correction”的叙述必须跟随真实系数范围调整。

**反思：在加入角色、转移和路由之前，先证明新增信号比匹配的随机/端点输入有增量价值。修复错误、梯度非零和表示改变，都是必要检查，不是机制有效性的替代证据。**

依据：[方案](第二阶段_Prompt设计深化_干预响应与结构控制.md)、[R³ 项目复盘](../R3Prompt/docs/R3Prompt_研究复盘与后续Prompt设计启示.md)。

## 3. RCCP：动作可能有效，但当前训练目标选不出来

首轮 60 次 RCCP-1 中有 55 次最终 α=0。GPPT 的 10 次最终全部为 0；与此同时固定 α=1 相对 frozen 平均 +3.49 个百分点。梯度并非不存在：GPPT 的 2000 次更新中，1982 次投影前 α<0，被 [0,1] 约束投回零。

更关键的是，GPPT fixed1 的平均 query accuracy 提高，但 support CE 比 frozen 高 0.02876。对当前 support CE 做下降，不一定走向泛化更好的固定校正。

**这里必须拆开两个问题：算子是否有用，以及少样本训练能否找到它。** 当前学习版没有兑现第二点，不能据此否认第一点；也不能从测试集看到 α=1 好，就把它当作已经解决的任务内选择策略。

后续报告比首轮更有说服力。head 达到既定正则化目标的数值收敛，并控制表示尺度后，GPPT unit 条件下 frozen/exact/tangent 分别为 26.45%/30.05%/30.23%。正确 exact/tangent 仍超过整体幅度匹配的 self 与接收者打乱对照。因此“全部只是 head 未收敛或整体缩放”已经不足以解释这些收益。

但 GraphMAE 同条件为 69.07%/67.70%/67.75%，仍负迁移；exact 与 tangent 也没有可靠优势差。这使合理定位收窄为“特定预训练表示上的固定结构校正”，而非通用的可学习非线性上下文 Prompt。

**反思：减少参数能降低估计负担，却不能保证训练信号方向正确。允许回到零也不会自动使训练找出有用非零动作。RCCP 值得保留的部分是固定校正的独立复现，而不是重新堆叠路由器。**

依据：[方案](第三阶段_RCCP图Prompt设计与验证方案.md)、[首轮诊断](../RCCP/results/诊断关键信息_2026-09-07.md)、[尺度诊断](../RCCP/results/尺度与head优化诊断判断_2026-09-07.md)、[最终机制对照](../RCCP/results/机制对照结果判断_2026-09-07.md)。

## 4. CNIP：提取到非加性响应，不等于提取到可泛化增量

CNIP 以 I=h11−h10−h01+h00 抵消单侧效应，再用 h00+λI 分类。其设计押注的是：这种特定约束，比直接利用单侧或联合提示更适合少样本任务。

六个 checkpoint 的描述性均值为：h00 35.98%，CNIP 35.10%，固定随机方向 36.00%，一阶响应 37.27%，自由融合 37.89%。60 个配对 cell 中 CNIP 对 h00 为 17 胜、1 平、42 负。GraphCL 的 +0.68 个百分点是局部探索性信号。

60 次 λ 最终全部为 +1，p/q 多数到达范数边界，support 响应并未消失。每种 checkpoint 的 support loss 都低于 h00，但 query 在四种 checkpoint 上下降。Gprompt 从 32.39% 降至 27.58%。

**较有依据的归因：四分支差分这个归纳偏置没有体现普遍优势，support 学出的响应不能稳定泛化。** 主效应被抵消能使公式突出“交互”，但尚无任务证据说明这些被抵消的效应应被舍弃。自由融合仅 20 个提示参数、同四分支路径，5/6 checkpoint 优于 17 参数的 CNIP，尤其值得重视。

但不能把差距全部解释成“交互信息无用”：自由融合同时改变基础表示尺度；学习方向与固定随机方向的最终范数不匹配。过拟合、幅度过大、尺度及方向选择尚未被充分分离。

**反思：选择一个数学上更特殊的量，会引入额外偏置；必须证明这个偏置适合分类。约束达到上限说明优化在使用预算，不说明需要更大预算。**

依据：[方案](第四阶段_CNIP中心邻域交互Prompt方案.md)、[首轮结果分析](../CNIP/results/首轮结果分析.md)。

## 5. STSP：有效先验尚未建立，不能直接跳到迁移失败

STSP 的 README 与验证文档仍写“未训练”，但本地已有 6 个 checkpoint 的阶段 B 结果，以及 186 份 stable 真实任务适配制品。其中常规网格为 6 checkpoint × 3 shot × 10 split=180 次，其余 6 次为 split 42。不能继续引用旧状态。

本次直接重算每个 checkpoint 的 20 个独立投影视图伪任务评估。准确率单位为 %：

| checkpoint | frozen | random | stable |
|---|---:|---:|---:|
| DGI | 33.50 | 33.17 | 34.17 |
| GPPT | 35.83 | 35.75 | 35.25 |
| Gprompt | 34.00 | 33.92 | 35.00 |
| GraphCL | 38.58 | 38.50 | 38.00 |
| GraphMAE | 36.75 | 36.75 | 37.42 |
| SimGRACE | 35.83 | 35.92 | 34.67 |

这里是 3-way 伪任务，均值大多靠近 33.33% 的均匀猜测准确率。stable 相对 random 三正三负，尚无稳定优势。DGI 的 query CE 从 frozen 22.72 降至 stable 1.80，但准确率只从 33.50% 到 34.17%；这更提示需要检查适配的数值条件与置信度，而不能仅凭 loss 大幅改善宣称学到了有效分类先验。GraphCL、GPPT、SimGRACE 的 stable 平均 JS 还高于 frozen，稳定性也不是所有 checkpoint 都改善。

真实任务现有制品全部是 stable，缺少 frozen/random/dual/meta-init 的配对运行。因此：

- 不能由历史 reference 表的分数差直接归因，头、适配日程和协议未在这些比较中充分统一。
- 缺少 E−D（有/无 JS）的对照，无法识别稳定性约束的独立作用。
- 缺少已成立的伪任务优势，尚不能把主要问题定位到“先验从伪任务向真任务迁移失败”。

还有尺度信号：DGI 5-shot 的 10 次系数范数均约 1，平均相对输入改变量约 1.626；GPPT、Gprompt、SimGRACE 分别约 0.0445、0.0358、0.0224。各基有效秩记录均为 8，故不能无证据断言基已经塌缩。较合理的待验证解释包括伪任务质量不足、内循环步长与尺度不合适、统一预算下适配幅度差异过大；当前不能确定哪一项主导。

**反思：额外元训练只是把先验估计移到另一个阶段，不自动提供可靠先验。应严格执行原方案的准入条件：先在独立伪任务上胜过随机基，再研究真实任务迁移；先有 E−D，再谈稳定性创新。**

依据：[方案](第五阶段_STSP稳定任务子空间Prompt方案.md)、[STSP 制品](../STSP/artifacts/)、[DGI 伪任务开发结果](../STSP/artifacts/cora_dgi_stable_b17/pretrain/pseudo_development.json)。以上 STSP 表为本次重算的描述性均值，未作显著性判断。

## 6. CDP：任务关联更直接，但“该保护什么”仍未验证

CDP 用 support 类均值差构造子空间 P，在这些方向上用自身替代部分邻域。它缩短了学习链路，但同时引入两个假设：P 能代表泛化的判别方向；这些方向上邻域混合过强、增加自身权重有利。

fair-v2 中，linear 的 60 次有 22 次 α=0，prototype 有 20 次。但 GraphMAE linear 的 α 均值达到 0.803，平均激活前相对扰动 19.75%，10 次 query accuracy 全部下降，均值 −1.76 个百分点；prototype 也下降。因此问题不全是没有启动动作，也不能仅靠更换分类头解释。

**当前支持的是“这个固定方向、单向收缩的组合没有稳定泛化收益”，尚不能把原因唯一定位到方向估计或动作形式。** 本批缺少 full/random 对照与固定 α 扫描，无法分辨真实类差方向是否更好，以及是否存在有用但训练没有选出的强度。

设计本身也提示了估计难点：1-shot 时 P 实质由支持样本几何决定，重命名单例类别不会改变 P；5-shot 的类均值仍有抽样误差。只训练一个 α，不等于只从标签估计了一个自由度，P 本身也是数据依赖估计。

**反思：标签参与构造信号，不代表信号就可靠；把“类别均值不同”进一步解释成“这些方向应当减少平滑”，仍需要实证桥梁。**

依据：[方案](第六阶段_CDP类差方向保护Prompt方案.md)、[fair-v2 分析](../CDP/docs/audit/fair_v2返回结果分析.md)。

## 7. 跨方案的研究反思

### 7.1 设计差异的筛选早于任务瓶颈的确认

阶段文档明确优先“设计差异”。这能避免表面改模块，但也容易让选题从“还有什么操作没被做过”出发。RCCP 的返回贡献、CNIP 的非加性响应、CDP 的聚合损伤，都需要先证明是当前任务可利用的机会。公式说明如何干预，不说明为何应干预。

这里批评的是证据顺序，并非主张放弃新颖性。下一轮应把“与已有方法不同”与“针对已测瓶颈”同时列为准入要求。

### 7.2 少参数不等于少假设，也不等于低估计风险

RCCP 只学一个标量仍可能选错方向；CDP 的单标量背后有 support 子空间估计；STSP 在线 8 个系数背后有 45,856 个离线基参数。控制参数越少，越依赖预设动作方向恰好正确。低维减少了方差，也可能带来强偏差。

### 7.3 support 优化成功与泛化成功被反复混在一起

RCCP 的有益固定动作反而使 support CE 略高；CNIP support 改善而 query 常下降；CDP 可有大动作但负迁移。由此不能自动推导出“再训练久一些”“再放大门”“再换初始化”能解决问题。

### 7.4 数值合同与研究主张需要两套通过标准

身份初始化、冻结哈希、合法 split、梯度和有限差分检查是可信运行的基础。它们回答“是否实现了指定操作”。随机信号、固定动作、幅度匹配、同头基线及独立评估才回答“指定操作是否值得做”。两套标准不能相互替代。

### 7.5 同超参数并不保证基线充分，同等运行次数不等于独立证据

RCCP 的 GraphMAE frozen 在 L-BFGS 下由 raw 60.44% 到 unit 69.07%，变化达 8.63 个百分点；CDP 中 DGI frozen linear 21.06%、prototype 35.89%。这说明表示尺度、正则化与头的选择足以影响研究判断。

不过 RCCP 最新诊断已排除了“仅由整体尺度或 head 未收敛解释收益”。不能把旧问题永久当作所有方案的统一借口。各项目的协议与参数量也不同，不应直接把跨项目 accuracy 排成机制优劣表。

相同 query、多 support seed 和多种历史 checkpoint 主要衡量条件于现有图与权重的敏感性。多轮利用同一 query 选择方案，即使没有 query 反向传播，也已构成开发过程。换 support seed 不会使旧 query 重新成为未见测试。

### 7.6 文档里的止损规则需要成为实际执行门槛

多份方案已经写明先做随机/简化对照、先验证原语、无增益则停止。实际材料显示：R³ 最小原语正证据未先成立，STSP 缺少关键方法组便已有大批 stable 网格。因此需要改进的是执行顺序，而非继续增加更完备的方案文字。STSP 状态文档与制品脱节也说明实验完成后应同步更新结论和缺项。

## 8. 下一步投入的具体取舍

1. **先固定可信基线。** 在独立开发任务中确定尺度处理、头、正则化和优化预算，保留 frozen linear/prototype；相同头下判断 Prompt 的增量，完整流程的比较另行解释。
2. **每个候选只验证一条新增主张。** 信号方法先过真实输入对匹配替代输入；动作方法先过固定动作对 no-op/简单动作；学习方法再证明能从 support 选出有益动作。
3. **保留 RCCP 的窄正结果。** 固定候选设置，在新的预训练 seed 与预先指定第二数据集独立复现；保留 GraphMAE 负结果，不恢复通用性叙述。
4. **R³ 与 CNIP 暂停结构扩张。** 如继续 CNIP，只做匹配幅度、尺度校准等少量诊断；无独立增量便归档，不再依赖复杂路由挽救。
5. **STSP 回到伪任务与内循环诊断。** 优先确认 frozen/random 的数值条件和分类能力，再补 dual/stable；这些成立前不扩大真实任务网格。
6. **CDP 只保留固定强度和方向对照。** 在独立开发协议比较 α 含零的固定候选与 full/random；若仍无方向特异收益，停止当前原语。
7. **提前写明通过与停止条件，保留未参与决策的评估数据。** 以实际值得投入的最小增益、负迁移比例和计算成本作决定，而非从大量格子中挑一个正结果。

这些实验已经积累了有价值的负证据和少量正证据。后续最重要的改变，是让每次实验都减少一个明确的不确定性：究竟缺信息、缺有用动作，还是缺从少样本中选动作的能力。

## 9. ASP：结构方向有局部价值，但未解决完整管线的瓶颈

以下三轮均运行于 2026-09-13，使用独立协议 `asp-node-v1`：Cora/CiteSeer × 九个现有 GCN checkpoint × 十个持久 5-shot 支持集，官方测试节点 1000 个；编码器冻结，单位余弦原型头，支持集平衡五折 CE 选择候选。三种方案没有梯度更新，不能描述为“训练了若干 epoch”。额外的 GPF+ 工程对照才进行了 200 步优化。

九权重等权描述性均值如下，准确率单位为 %，增量为百分点：

| 方法 | Cora Accuracy | 对 frozen Δ [95%CI] | CiteSeer Accuracy | 对 frozen Δ [95%CI] |
|---|---:|---|---:|---|
| frozen | 36.19 | — | 31.31 | — |
| ASP | 37.20 | +1.00 [+0.48, +1.54] | 31.68 | +0.37 [−0.05, +0.74] |
| SIP | 51.22 | +15.03 [+13.78, +16.34] | 41.08 | +9.77 [+7.89, +11.88] |
| SCP | 39.38 | +3.19 [+2.35, +4.24] | 34.69 | +3.38 [+2.75, +4.02] |
| 原始属性原型 | 45.61 | +9.42 [+7.65, +11.31] | 45.45 | +14.14 [+12.73, +15.51] |
| 扩散属性原型 | 71.13 | +34.94 [+33.28, +36.68] | 61.11 | +29.80 [+26.80, +32.62] |

这里不能把 90 个 checkpoint × split cell 当成 90 个独立重复。原统计按 split 成组抽取九个权重；属性基线不依赖权重，在九列重复，其有效支持抽样仍只有十组。以下“所有权重未超过”均指各权重的十组均值，不指每一个 cell。

ASP 操作为 `X(a)=X+a(PX−X)`，六个候选同时允许平滑与锐化。预设工程门槛要求两数据集各至少 +1pp、配对区间下界大于零、至少 6/9 权重正向且 F1 不降。CiteSeer 只有 +0.37pp，区间跨零，明确未通过。两数据集的 cell 负迁移率分别为 26.7% 和 37.8%；DGI 上分别由 36.08% 降至 34.37%、44.64% 降至 44.34%。

**失败不能归为“没有动作”或“真实结构完全没用”。** 本次重算显示，两个数据集各 90 个 cell 只有 1 个选择 a=0；选择两个边界值 −0.5/1 的次数分别为 80/90、84/90。ASP 相对相同预算的节点置换残差，描述性增量为 +2.34/+1.80pp，说明真实对应关系有价值。但相对固定 a=0.5 的增量只有 +0.42/+0.15pp；这些新增差值未重做显著性检验，不能据此宣称选择器已可靠，也不能把边界偏好解释成应扩大搜索范围。

**较有依据的归因：一个全局输入平滑/锐化参数，只能提供有限的任务适配，未弥补当前编码器与原型读出的整体不足。** 它是否受原语能力、候选覆盖或支持集选择误差主导，仍未完全分离。没有测试标签无关的进一步证据，不能从边界选择直接推导“更强平滑会成功”。

需要修正第二轮设计中的一句解释：原始属性分类优于冻结表示分类，并不足以证明“预训练表示存在不可恢复的信息损失”。这里同时包含编码器、表示尺度和原型读出限制；没有同表示充分线性探测等诊断，最多只能说**现有冻结编码器＋原型头没有充分兑现原始属性可达的分类能力**。

**反思：优先验证当前管线的主要瓶颈，再选择输入干预；保留真实结构优于随机的局部证据，但不要把它替代为完整方案超过 frozen 或强基线的证据。**

依据：[ASP 设计](../ASP/docs/01_spectral_design.md)、[综合结果](../ASP/REPORT.md)、[首轮原始制品](../ASP/results/round1_spectral/)、[汇总统计](../ASP/results/combined_summary.json)。

## 10. SIP：前端已经能分类，重新编码没有体现额外价值

SIP 先对原始属性做十步重启扩散得到 U；由当前支持样本的 U 原型产生软类别分配 Q，由其原始属性类均值得到 M，然后输入 `(1−a)X+aQM` 到冻结 GCN。每个内部折都重新构造 Q、M 和表示，排除留出标签；最终再用完整支持集重建。不能把它误记为复用全支持语义造成的已知标签泄漏。

SIP 对 frozen 的 +15.03/+9.77pp 是真实的匹配管线收益，但完整准确率 51.22%/41.08% 仍比不经过 GCN 的扩散属性原型低 **19.91/20.03pp**，九个权重的均值全部落后。CiteSeer 上甚至低于原始属性原型 4.37pp。DGI 是反例尤为明显的权重：Cora 从 36.08% 降至 34.04%，CiteSeer 从 44.64% 降至 25.87%；九权重均值的大幅提高不能掩盖这种兼容性差异。

**SIP 不是“语义信号无价值”的失败。** 本次从原始记录重算，完整方案相对节点打乱重构为 +16.36/+11.90pp，相对不扩散属性的重构为 +12.31/+11.04pp，相对固定 a=0.5 为 +7.07/+5.33pp，均为描述性配对均值。结构、节点对应和候选选择确有值得保留的局部证据。选择 a=1 的比例为 67/90、71/90，说明大多数 cell 采用完整重构，而非完全没有启动输入适配。

更关键的对照是 `transport_direct`：直接用 Q 分类，与 `diffused_raw` 的 argmax 相同，仅温度和概率不同。也就是说，生成 Prompt 的前端本身已是一个可直接使用的分类器；经过类均值重构、冻结编码器和第二次原型读出后，平均性能反而降低。**完整流程没有证明冻结编码器在这条任务语义路径上增加了价值。**

合理但未隔离的解释包括：类均值重构可能压缩类内差异，软分配错误可能被带入后续编码，重构输入与既有预训练分布不兼容。现有对照能定位“新增后处理链路没有净收益”，尚不能唯一判断损失主要来自重构、GCN 变换还是最终原型头。不能把推测写成已证明的压缩或分布偏移根因。

**反思：当 Prompt 构造器已经利用支持标签产生强预测时，必须把它直接读出作为首要对照。击败较弱 frozen 或某个 GPF+ 配置，不等于预训练提示机制增加了独立价值。也不应为了保留输入 Prompt 的形式，强制经过没有证明有益的编码链路。**

依据：[SIP 设计](../ASP/docs/02_semantic_design.md)、[逐折重构实现](../ASP/semantic.py)、[第二轮制品](../ASP/results/round2_semantic/)、[综合报告机制对照](../ASP/REPORT.md)。

## 11. SCP：输入校准有效，但不能把收益全部归给结构或自适应

SCP 使用 `X(s,a)=s[X+a(PX−X)]`，七个尺度、三个结构强度，共 21 个固定候选，以支持集五折选择。对 frozen 的 +3.19/+3.38pp 通过了项目工程门槛，两数据集均为 8/9 权重均值正向。因此应写成“有限校准收益成立，但研究主张未充分成立”，不应写成完全无效。

| 配对比较 | Cora Δpp [95%CI] | CiteSeer Δpp [95%CI] | 支持的判断 |
|---|---|---|---|
| SCP − scale-only | +0.85 [+0.53, +1.15] | +0.78 [+0.50, +1.04] | 在既定选择协议内，允许结构残差有额外收益 |
| SCP − 固定尺度16 | −0.63 [−1.40, +0.32] | +1.05 [+0.59, +1.49] | 自适应组合没有在两数据集都超过简单固定校准 |
| SCP − 扩散属性原型 | −31.75 [−33.27, −30.51] | −26.42 [−29.36, −23.33] | 完整预训练输入适配仍未达到强简化管线 |

scale-only 相对 frozen 已有 +2.34/+2.60pp，说明输入幅度是不可忽略的因素。SCP 的小幅结构增量可以保留，但不能把全部 +3pp 都归给结构 Prompt；SCP 对固定尺度的比较同时改变了候选选择和结构操作，也不能当成纯选择器贡献。尤其 Cora 的固定尺度16准确率为 40.01%，高于 SCP 的 39.38%，不支持“支持集自适应必然优于固定设置”。

输入缩放与输出温度不是同一个操作：单位余弦原型对输出正标量缩放不变，但含偏置、非线性的冻结 GCN 对输入缩放可以改变方向。现有行为测试和实验支持尺度敏感，**不支持直接断言 checkpoint 使用了错误预处理**。全局无标签中心化的效果又因权重而异，DGI 明显退化，也不能用“去除公共偏置”统一解释和修复所有低分。

**反思：输入尺度应先作为冻结编码器兼容性与基线校准的诊断维度。校准收益、结构增量、选择器收益和完整管线价值必须分开报告。小规模固定候选的成功不是新的预训练机制证据，更不是尚未验证的新颖性结论。**

依据：[SCP 设计](../ASP/docs/03_scale_design.md)、[候选选择实现](../ASP/scale.py)、[第三轮制品](../ASP/results/round3_scale/)、[中心化诊断](../ASP/results/centering_diagnostic.json)。

## 12. 三轮新增反思：先证明预训练链路值得保留，再讨论如何提示

这三轮改善了早期工作的一些问题：采用简单可控动作，真正排除内部留出标签，加入真实/随机对应、固定动作和简化属性分类器，并在门槛失败后记录下一轮设计。完整网格含三轮候选和 GPF+ 共 4140 条记录，已有预测与冻结审计；本次确认其文件内容与审计清单一致。失败不能笼统归结为“没实现”“没选出非零动作”或“没有任何有效信号”。

新增的主要问题是：**对较弱冻结管线的修补，被赋予了超过现有证据的机制含义。** SIP 和 SCP 的工程门槛通过，并未让完整管线胜过强属性基线；真实信号优于随机输入，也未证明后续预训练编码器带来额外价值。

后续判断应遵守以下顺序，作为第 7 节反思的补充，而不是恢复第 8 节已被历史决策覆盖的旧主线：

1. **先定位 head、尺度与表示的限制。** 同表示比较原型与充分调节的线性读出；没有分离这些因素前，不把低准确率命名为“预训练信息丢失”。
2. **先过强简化对照，再赋予完整流程研究价值。** 对语义重构，直接 Q 分类和扩散属性分类不可省略；对输入校准，scale-only 和事先锁定的固定尺度不可省略。
3. **分别证明信息、动作、选择和完整链路的价值。** ASP/SIP 优于置换信号只回答第一类问题；SCP 优于 scale-only 不回答自适应是否必要。不要用一个正差值覆盖其余未成立的环节。
4. **保留权重依赖和局部正结果。** SIP 的 DGI 退化、SCP 的有限结构增量均需报告；九权重平均不能替代每个 checkpoint 的判断，也不能因存在弱权重就抹去全部配对收益。
5. **把原语筛选失败与潜在方法上限区分开。** GPF+ 在此仅是 ProG-adapted、零提示初始化、同原型头、两个固定学习率的工程对照，不代表官方最佳成绩；不能由击败它宣称领域领先，也不能由输给它证明该原语永远无用。
6. **不要直接用更复杂路由挽救当前候选。** 若同头强基线缺口仍达十几个到三十多个百分点，先验证候选动作本身及编码链路；支持集 CE 或 CV 选择并不自动提供负迁移风险保证。增加 identity/reject 动作也需要独立证据，不能直接称为“安全”。
7. **停止规则应区分工程通过与研究通过。** 本批保留输入校准、真实语义对应和失败诊断作为可复用证据，暂不恢复 ASP/SIP/SCP 为新 Prompt 主线。未来重启应有新的、可证伪的瓶颈证据，并预先保留未参与开发的图或独立预训练权重；继续换同图支持集种子不构成独立确认。

本轮最应保留的教训是：**先问完整预训练适配管线是否增加了价值，再问如何让输入 Prompt 更复杂。** 可信负结果的价值在于缩短下一次验证路径，而不是把局部正结果扩写成尚未成立的新方法。

证据入口：[ASP 综合报告](../ASP/REPORT.md)、[既有逐概率审计及文件清单](../ASP/results/local_audit.json)、[逐权重结果](../ASP/results/per_checkpoint.csv)、[源码快照](../ASP/snapshots/)。本次更新没有开展新的外部新颖性检索，也未新增 GPU 实验。

## 13. RGP-MAE：重构几何约束成立，但没有转化为任务判别方向

RGP-MAE 的主张是：利用 GraphMAE 的重构解码器和局部响应 Jacobian 构造提示子空间，在保持干净表示响应的同时抑制重构敏感方向，再用少量系数和线性 head 适配 5-shot 分类。这个设计把 GraphMAE 的预训练目标直接引入 Prompt 选基，减少了 R³Prompt、CNIP 一类方法中的多级路由和复杂控制器。

结果支持“工程实现和几何约束确实执行了”，但不支持“重构几何因此提供了下游分类增益”。RGP-MAE 首轮 220 次适配的均值为：

| 方法 | Cora | CiteSeer |
|---|---:|---:|
| frozen | 76.57 ± 1.97 | 51.61 ± 3.82 |
| RGP | 76.52 ± 2.04 | 51.25 ± 4.07 |

配对 query 差值为 Cora `−0.05 pp [−0.18, +0.06]`、CiteSeer `−0.36 pp [−0.68, −0.03]`。CiteSeer 中 RGP 相对 random-preserve 和 gain-preserve 分别提高约 `+0.79` 和 `+1.15 pp`，说明它能减少一些错误提示方向造成的损失；但它仍没有超过无提示 frozen。RGP 与去掉保持项的 `rgp_no_preserve` 只相差约 `−0.02 pp`，因此当前重构保持项没有独立性能证据。

第二轮诊断进一步排除了几个较容易但不足的解释：raw/RMS 坐标配对 80/80 通过，最大目标函数差为 `1.13e−10`；L-BFGS head 拟合全部收敛；振幅 `0.25/0.5/1.0` 在两个数据集上都没有超过 frozen。`rgp_no_preserve` refit 相对 frozen 的差值为：

| 数据集 | α=0.25 | α=0.5 | α=1.0 |
|---|---:|---:|---:|
| Cora | −0.06 pp | −0.11 pp | −0.20 pp |
| CiteSeer | −0.07 pp | −0.10 pp | −0.33 pp |

预先定义的 Stage C 门槛因此为 false，不应再通过增加半径、扩大 decoder 或堆叠更复杂的 Prompt 控制器来挽救当前组合。

### 13.1 较有依据的失败归因

**第一，选基目标与下游任务目标错位。** 候选 Prompt 空间本身对 support 分类梯度的覆盖率只有 Cora 约 2.20%、CiteSeer 约 3.45%。在候选空间内部，RGP 子空间保留的任务梯度比例约为 Cora 19.5%、CiteSeer 2.5%。这表示重构几何选出的方向大部分没有落在当前 5-shot 分类真正需要的方向上，CiteSeer 尤其接近任务无关。RGP 使重构响应变小、表示仍发生变化，并不能说明变化提高了类间可分性。

**第二，支持集适配与 query 泛化脱钩。** CiteSeer 上 RGP refit 的支持准确率约 57%，略高于 frozen 的约 56.7%，但 query 仍然下降。当前自由度可以改善支持集拟合，却没有形成稳定的跨节点类结构。这与“少量系数足以安全选择预训练几何方向”的假设不一致。

**第三，动作强度放大了错误方向。** CiteSeer 的负差值随振幅增加而扩大，α=1 时达到 −0.33 pp。首轮中 CiteSeer 的 RGP 系数还经常触及半径边界；第二轮表明减小振幅只能减轻损失，不能把方向变成正收益。因此边界触发不是“应该继续放大半径”的证据。

**第四，保持重构的约束没有带来可测的净收益。** RGP 与 `rgp_no_preserve` 几乎相同，说明当前保持项既没有解决任务错位，也没有提供足以抵消额外计算的泛化保护。它更像是一个表示几何约束，而不是有效的下游正则化。

### 13.2 不能据此推出的结论

本结果不能证明 GraphMAE 的重构目标对所有下游任务都无用，也不能证明所有 Jacobian 子空间方法都无效。它只说明：在当前 GraphMAE checkpoint、Cora/CiteSeer 5-shot 协议、当前输入 Prompt 作用位置和当前线性读出下，重构几何没有形成稳定的 query 增益。RGP 在 CiteSeer 上优于 random/gain-only 的结果也应保留，但应解释为“降低负迁移”，而不是“发现了有效判别方向”。

### 13.3 对后续 Prompt 设计的启示

1. **重构保持与任务有效性必须分开验收。** 重构误差下降、响应能量被抑制、表示发生变化都只能证明几何目标被执行，不能替代匹配的 query 泛化证据。
2. **任务标签必须进入选基，但不能只最大化梯度覆盖率。** CiteSeer 的 gain-only 子空间覆盖率更高，却仍显著低于 frozen；下一方案应同时约束任务梯度、表示保持和跨 split 稳定性。
3. **先做最小原语，再决定是否扩展。** 如果未来重新验证，只应先做 class-balanced support 梯度与重构 Jacobian 的联合选基，限制 `K=1,2` 和小振幅，并保留 random、gain-only、当前 RGP 三个负对照。没有跨两个数据集的预设增益，不进入完整 Stage C。
4. **不要把更复杂的 decoder 或更大的半径当作默认修复。** 本轮已显示问题集中在方向选择，而不是单纯动作幅度或 head 未收敛。

**研究判断：RGP-MAE 应归档为“重构几何约束可实现、但当前缺少任务判别增量”的负结果。** 它为后续研究留下了一个清晰的诊断边界：下一次新 Prompt 必须先证明选出的方向与少样本任务相关，再讨论如何利用 GraphMAE 的预训练目标。当前不恢复 RGP-MAE 为主线，也不再用局部优于随机 Prompt 的结果支持更强的机制叙述。

依据：[RGP-MAE 首轮分析](../RGP_MAE/results/5090_gpu0_20260913_5shot/结果分析.md)、[第二轮判断分析](../RGP_MAE/artifacts/server/5090_gpu0_v2_diagnostics_r02/判断分析.md)、[第二轮验证结果](../RGP_MAE/artifacts/server/5090_gpu0_v2_diagnostics_r02/verification.json)、[配对比较](../RGP_MAE/artifacts/server/5090_gpu0_v2_diagnostics_r02/paired_summary.csv)。

## 14. ContextPrompt-CSEP：交叉支持证据没有提供独立增量

CSEP（Cross-Support Evidence Prompt）针对的是一个具体问题：同一组 5-shot 支持样本拟合出的预测，其共同错误可能被误当作属性边证据。实现把每类支持节点拆成互斥的 A/B 子组，分别拟合岭回归，再用交叉预测一致性重加权属性图。这个问题意识和交叉项恒等式是清楚的，但不能把它们本身写成方法创新：重启传播、闭式岭读出、原图/属性图融合、支持集条件化结构和任务相关边权在已有工作中均有对应先例。当前实现的实际归属仍是“在已有固定双图基线上的支持证据消融”。

正式屏选使用 DGI、GraphMAE × Cora、CiteSeer × 10 个新支持集 × 7 个方法，共 280 条记录，物理 GPU0 完成，用时 30.664 秒。编码器冻结，所有版本使用相同传播过程、支持集、查询池和匹配的岭读出。CSEP 的 test Accuracy 如下，单位为 %：

| 数据集/checkpoint | 固定双图 | 同组证据 | 交叉证据 | 交叉−固定 | 交叉−同组 |
|---|---:|---:|---:|---:|---:|
| Cora/DGI | 78.96 | 79.00 | 79.00 | +0.04 | 0.00 |
| CiteSeer/DGI | 68.99 | 69.13 | 69.09 | +0.10 | −0.04 |
| Cora/GraphMAE | 76.30 | 76.54 | 76.56 | +0.26 | +0.02 |
| CiteSeer/GraphMAE | 59.67 | 59.94 | 59.76 | +0.09 | −0.18 |

四个组合均未通过事先规定的门槛。Cora/DGI 的节点对应置换达到 79.05%，高于交叉证据的 79.00%；标签置换基本回到固定基线。交叉项的数学恒等式、互斥拆分、均匀 no-op 和 lambda 锁定检查均通过，但这些属于实现可信度，不是下游有效性证据。

较有依据的归因是：交叉拆分减少了同一支持池预测的共享项，却没有增加足够的独立任务信息；五个拆分仍共享同一图、编码器和有限支持池，不能视为无条件独立的交叉拟合。交叉证据与同组证据非常接近，说明本轮收益主要来自普通的任务相关边重加权或支持集波动，无法归因于“消除共同错误”。不能把 CiteSeer 的负差值解释为交叉思想本身不可能，也不能通过增加温度、路由器或更多选择器来挽救已失败的原子机制。

**研究判断：CSEP 应归档为“有清晰问题定义和可审计构图，但没有独立 query 增量”的负结果。** 它保留的价值在于给出了一个可复用的反事实对照：同组与交叉支持证据在相同内部分类器下几乎等价。若未来重新使用该思想，必须在未参与开发的图或 checkpoint 上检验，并证明其信号超过嵌入相似度、分类器预测和节点置换带来的收益。

依据：[CSEP 设计](../ContextPrompt/docs/16_cross_support_redesign.md)、[GPU0 结果](../ContextPrompt/docs/17_cross_support_screen_result.md)、[原始归档](../ContextPrompt/results/redesign_cross_screen_v2.tar.gz)。相关工作边界包括 FLGC（https://arxiv.org/abs/2111.07942）、AM-GCN（https://arxiv.org/abs/2007.02265）、GPR-GNN（https://arxiv.org/abs/2006.07988）及支持消息适配的 MAGPrompt（https://arxiv.org/abs/2602.05567）；本段不作穷尽性新颖性检索结论。

## 15. ContextPrompt-激活响应诊断：激活保持不是已证实的创新点

在 CSEP 之后，设计了激活响应诊断，检验属性上下文进入冻结两层 GCN 时，跨越中间 LeakyReLU 激活区间是否是负迁移的关键原因。属性图和传播参数完全沿用固定双图；比较真实输入干预、固定原激活模式的一阶响应、等幅一阶响应、打乱激活对应、固定双图和 no-op。该实验的定位是机制前提诊断，不是把一阶 Taylor 近似、固定门控或输入平滑重新命名为新 Prompt。

最近邻归属必须明确：GPF 已有冻结 GNN 的输入 Prompt，DAGPrompT 已有分布感知和分跳 Prompt 以及低秩消息适配，MAGPrompt 已有冻结骨干上的消息重加权和提示向量；因此“把干预放进中间层”“保留激活模式”或“改变消息路径”本身不足以构成新颖性。更基础的输入平滑、重启传播和线性读出也分别已有对应先例。当前实验只检验一个尚未证实的机制假设，不能据此提出论文方法名或优先权主张。

GPU0 共完成 DGI、GraphMAE × Cora、CiteSeer × 10 个新支持集 × 7 个方法，共 280 条，执行 31.758 秒；排除此前 405 组完整支持集合。编码器张量冻结哈希保持不变，真实前向与手算分支一致，自动微分 JVP 相对误差最大为 9.949e−6，no-op 预测与固定基线一致。test Accuracy（%）如下：

| 数据集/checkpoint | 固定双图 | 真实干预 | 激活保持一阶 | 等幅一阶 | 打乱激活 |
|---|---:|---:|---:|---:|---:|
| Cora/DGI | 76.66 | 77.11 | 77.06 | 77.06 | 76.69 |
| CiteSeer/DGI | 68.57 | 68.50 | 68.44 | 68.42 | 68.51 |
| Cora/GraphMAE | 75.85 | 75.57 | 75.57 | 75.57 | 75.59 |
| CiteSeer/GraphMAE | 57.24 | 58.22 | 58.22 | 58.22 | 58.08 |

激活保持相对固定双图的差值分别为 +0.40、−0.13、−0.28、+0.98 个百分点；但相对真实输入干预分别为 −0.05、−0.06、0.00、0.00。Cora/DGI 和 CiteSeer/DGI 的一阶−固定 95% 配对 bootstrap 区间分别为 [−0.15,+0.96] 和 [−1.08,+0.79]。CiteSeer/GraphMAE 的 +0.98 个百分点与真实干预完全相同，不能归因于激活保持。等幅对照也没有改变判断，锁定 fixed lambda 的敏感性结果保持相同结论。

四个组合的激活符号跨越比例为 1.899%、2.222%、1.191%、0.145%；非线性余项相对真实响应范数为 1.739%、2.705%、8.914%、7.326%。这些数值说明扰动确实造成少量激活变化，但没有建立“激活跨越导致分类负迁移”的因果链。余项是全局范数统计，不能推广到其他扰动方向、幅度或更深编码器。

**较有依据的失败归因：** 在当前属性平滑方向和冻结 checkpoint 上，一阶激活保持主要复现了真实输入干预的响应，未提供额外的可泛化分类信息；CiteSeer/GraphMAE 的正向变化由普通真实输入干预即可获得。因而不能将其称为“激活保持保护了预训练知识”，也不能以 JVP 一致、激活模式稳定或响应范数匹配来代替 query 增益证据。

**研究判断：** 激活响应诊断应归档为“实现和机制测量通过、核心假设未通过”的负结果。停止在该原子上添加可训练门控、风险路由或更大超参数网格。下一候选必须提供不等价于原始特征平滑、冻结表示相似度、已有分类器预测和局部线性响应的新信号，并先通过最小动作、匹配幅度、随机/置换和留出 checkpoint 对照。

依据：[激活响应协议](../ContextPrompt/docs/18_activation_response_diagnostic.md)、[GPU0 结果与归因](../ContextPrompt/docs/19_activation_response_result.md)、[原始归档](../ContextPrompt/results/redesign_activation_screen.tar.gz)。本轮使用了此前反复观察的官方查询池；新支持种子只用于机制初筛，bootstrap 只描述该查询池上的支持抽样变化，不是独立测试或跨图泛化保证。

## 16. 当前总判断：基础方案可复用，创新主张仍未成立

截至 2026-09-15，ContextPrompt 已经完成固定双图、支持证据、残差、多尺度、RGP-MAE 和激活响应等多个方向的实现与 GPU0 诊断。现有证据可以支持三种表述：

1. 固定属性上下文在当前 Cora/CiteSeer 5-shot 图和 DGI 配置上有稳定的条件收益，适合作为强基线和适配诊断。
2. 多个新增机制能够被严格实现、冻结和审计，但支持损失下降、响应非零、数学恒等式成立或优于随机对照，都没有自动转化为独立 query 泛化收益。
3. 目前没有足够证据把 ContextPrompt 命名为具有明确原创机制的独立方法。最有价值的产出是可复用的失败归因、匹配对照和研究边界，而不是继续包装已失败组件。

若继续追求创新，应改变可利用的信息或作用位置，并在设计阶段完成直接最近邻对照、任务瓶颈证据、等容量控制和未参与开发的留出验证。若这些条件不能同时满足，应把项目定位为冻结图预训练模型的系统适配评估与负结果分析，保留固定双图的工程价值，不对学术新颖性作超出证据的承诺。
